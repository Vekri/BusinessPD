Business PD assessment

One application in, a probability of default out, with every stage of the review shown in order.

Business problem

A lender has to decide, for every business loan, how likely that borrower is to default. The file already contains the facts: revenue, profit, debt, assets, cash flow, loan size, credit score, debt-to-income, recent delinquencies, and years in business.

Reading those facts one file at a time is slow, and two reviewers can weigh the same numbers differently. The book also needs a stored score so a later question can find the latest result for a customer, an industry, or a risk cutoff.

The label used here is a teaching target: 0 means Good and 1 means Bad. A live book would use the institution’s own default policy. The risk bands below 5%, from 5% to 10%, through 20%, and above 20% are settings of this project.

How this helps

One review, every file

The same checks, ratios, and model run for each application, so the score is comparable across the book.

A number and a class

The result is a probability of default and a risk class the reviewer can read without opening the model file.

The reason stays visible

Each stage is written down: the inputs, the checks, the ratios, the model drivers, and the band the score fell into.

The book stays queryable

The customer, the loan, and the prediction are stored, so a later lookup or a plain-language question reads the same record.

Architecture

A synthetic book is cleaned, turned into ratios, split, and used to train one logistic model. Scores are stored in PostgreSQL. The API is the only door the page, the tools, and the question router use.

Synthetic book→ Clean, ratios, split→ Logistic model→ PostgreSQL→ FastAPI

How the book was built

  1. Synthetic data. 10,000 businesses, seed 42. About 23.7% are labeled Bad.
  2. Cleaning. Blank ids, duplicate ids, missing numbers, and out-of-range values are rejected. Values are not clipped.
  3. Ratios. Debt to asset, loan to revenue, profit margin, and cash-flow coverage.
  4. Split. Stratified 80/20 on the label, seed 42. Train 8,000, holdout 2,000.
  5. Training. Scaler and logistic regression fit on the training file only. Class weights are balanced.
  6. Holdout. ROC-AUC 0.884, Gini 0.767, KS 0.615. The score ranks risk. It is a ranking score from balanced training, so the probability sits above the observed default rate.
  7. Storage. Schema, then one customer, one application, and one score per business.
  8. Access. SQL reports, the API, Docker, six MCP tools, the question router, and this page.

What you will see

Enter an application, or use Higher risk and Stronger file, then choose Run assessment. The review appears in this order:

  1. Application received. The figures you entered.
  2. Data checks. Eight rules, each pass or fail.
  3. Banking ratios. The four ratios and the formula behind each one.
  4. Model score. The strongest drivers and whether each one raises or lowers default risk.
  5. Risk class. The probability and the band it falls in.
  6. Saved to the book. Customer, scored application, and prediction.
  7. Assessment. One sentence with the business, the probability, and the class.
